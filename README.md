# Rules vs LLMs – Take‑Home Assignment

## Overview
This repository contains a small benchmark that compares three different approaches for calculating Indian personal‑income tax:

1. **Pure rule‑based engine** – deterministic calculations derived from the Income‑Tax Act.
2. **LLM‑in‑the‑loop** – a Gemini model is prompted with the statutory text each time it needs to compute a tax component.
3. **LLM‑compiled rules** – the statutory text is parsed once by Gemini to produce a JSON rule set, which is then used for fast, repeatable calculations.

The goal is to explore how well a large language model can understand tax language, extract the required numeric values, and whether a one‑time compilation step yields more reliable results than repeatedly prompting the model.

## Role of AI
- **`project_a/parser.py`** uses the Gemini API to convert natural‑language user descriptions (e.g., "My gross salary is 12 L and I pay 20k rent per month in Bangalore") into a structured JSON payload.
- **`project_a/impl_llm_runtime.py`** demonstrates the *runtime* approach where the LLM is consulted for every rule during tax calculation.
- **`project_a/impl_llm_compiled.py`** shows the *compiled* approach: the LLM reads the tax law once, produces a JSON rule set, and the rest of the computation is deterministic.

All AI interaction is confined to these modules; the core tax logic remains pure Python and can be run offline.

## Folder Structure
| Folder | Purpose |
|--------|---------|
| `project_a/` | Main tax‑calculation project. Contains source code, rule definitions, data, and tests. |
| `project_a/data/` | Test inputs: `text_cases.json` (50 natural‑language tax profiles) and other CSV/JSON files used by the benchmark. |
| `project_a/parser.py` | Gemini‑based parser that extracts tax fields from free‑text queries. |
| `project_a/impl_llm_runtime.py` | Implementation that queries Gemini for each rule at runtime. |
| `project_a/impl_llm_compiled.py` | Implementation that uses a JSON rule set generated by Gemini once. |
| `project_a/rules/` | Statutory rule text files (`*.txt`) and the compiled JSON specifications (`fy2024_25.json`, `fy2025_26.json`). |
| `project_a/tests/` | pytest suites for the three implementations and for the parser. |
| `project_a/scripts/` | Helper scripts, e.g., `generate_test_cases.py`. |
| `project_b/` | placeholder for a future data‑quality project (currently contains detector modules). |
| Root files | `README.md` (this file), `AI_USAGE.md` (explanation of AI decisions), `DECISION_MATRIX.md` (comparison results), `RESULTS_A.md` / `RESULTS_B.md` (benchmark outputs), `requirements.txt`, `Makefile`, `.env.example`. |

## Quick Start
1. Install the dependencies:
   ```powershell
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
2. Set up your Gemini API key in a `.env` file (copy `.env.example`).
3. Run the parser on a sample query:
   ```bash
   python -m project_a.parser
   ```
4. Execute the full benchmark:
   ```bash
   make run-all   # or python -m project_a.run_all
   ```

The results will be written to `RESULTS_A.md` and `RESULTS_B.md` and can be inspected alongside the decision matrix.
